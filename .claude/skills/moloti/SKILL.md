# moloti — само-пробуждающийся «молоти»-будильник

Владелец: «иногда останавливаешься, даже когда сказано молотить». Этот скилл ставит фоновый
harness-**Monitor**, который раз в N минут печатает событие → приходит notification → сессия
просыпается сама, даже если «встала». На пробуждении: перепроверяю usage+контекст и, если не был
дан прямой приказ стоп, беру верхний невыполненный пункт беклога и молочу дальше.

## Аргументы

- `/moloti` — вооружить с текущим периодом (или дефолт **20** мин, если ещё не задан).
- `/moloti 10` — период 10 минут (любое целое). Меняется **на лету** — работающий цикл подхватит
  на следующем тике, перезапуск не нужен.
- `/moloti off` (или `stop`/`выкл`) — погасить будильник (прямой приказ стоп).

## Как вооружать (идемпотентно)

`SK=<repo>/.claude/skills/moloti` · `UID=$(id -u)` · state `/tmp/moloti-$UID.min` · lock `/tmp/moloti-$UID.lock`.

1. **Период в state-файл** (если дан аргумент-число — записать его; иначе оставить как есть, а при
   отсутствии файла — записать `20`):
   ```bash
   echo 20 > /tmp/moloti-$(id -u).min   # или заданное N
   ```
2. **Проба живости** (НЕ через TaskList — Monitor'ы там не видны; берём OS-lock):
   ```bash
   flock -n /tmp/moloti-$(id -u).lock true && echo FREE || echo BUSY
   ```
   `BUSY` → будильник уже живёт (инкумбент держит lock); ничего не запускать, период уже обновлён
   в state — просто подтвердить. `FREE` → живого нет, запустить (шаг 3).
3. **Запустить ОДИН Monitor** (только при `FREE`):
   `Monitor(command: "bash <repo>/.claude/skills/moloti/nudge-loop.sh", description: "moloti self-nudge", persistent: true)`.
   Сохранить его task-id: `echo <task_id> > /tmp/moloti-$(id -u).taskid` (пригодится для `off`).
   Скрипт сам-singleton по flock → даже случайный дубль мгновенно выходит.
4. Коротко подтвердить владельцу период (без спама).

## Погасить (`off`)

`TaskStop` по сохранённому id (`cat /tmp/moloti-$(id -u).taskid`), затем `rm -f /tmp/moloti-$(id -u).min
/tmp/moloti-$(id -u).taskid`. Сказать «🔴 moloti off». Это и есть «прямой обратный приказ» — пока не
вооружат снова, само-пинков не будет.

## Что делать на КАЖДЫЙ пинок (`moloti_nudge`)

Пришло событие `{"moloti_nudge":true,...}` — это НЕ сообщение владельца, а мой будильник. Порядок:

1. **usage-check ПЕРВЫМ** (`self` через usage-check.py). **Бюджет-гард проекта:** если в 5-часовом окне
   осталось <5% (использовано >95%) — НЕ возобновлять, остановиться, оставить запас, сказать об этом.
   Гард важнее «молоти».
2. **context-check.** Если контекст занят высоко (≳75%) — сделать `/self-compact` (он сам продолжит
   после сжатия). Иначе — дальше.
3. **Само-проверка «молочу ли»:**
   - Уже активно работаю над задачей → тихо продолжаю (событие не сбивает фокус, владельцу не пишу).
   - Простаиваю / «остановился» / жду вопрос, которого не требуется → **МОЛОТИ:** беру верхний
     невыполненный из `docs/BACKLOG.md` (Next/🔴/🟡) или продолжаю текущее и работаю дальше.
   - Жду ввод, который есть ТОЛЬКО у владельца (напр. слух/тест с телефона) — не выдумываю работу
     ради работы; беру следующий пункт беклога, который двигается без него.
4. **Тихо.** Не слать владельцу сообщение на каждый тик (мирроринг и так всё покажет). Пишу, только
   если реально возобновил работу после простоя или есть что доложить.

## Заметки

- Период живёт в state-файле → переживает пробуждения; на компакт-резюме Monitor обычно ещё жив
  (проба `BUSY`) — повторный `/moloti` просто подтвердит, дубля не будет.
- «Прямой приказ стоп» = `/moloti off` ИЛИ явные слова владельца «стоп/пауза/хватит молотить». В
  последнем случае — вызвать `off`, чтобы будильник не будил вопреки приказу.
